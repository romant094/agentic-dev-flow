## Open findings carried over

- **A2, A4 — three parses per session, "unmeasured" encoded three ways** (`DF:21-36`). Fixed: one
  parse, `null` with a coverage reason.
- **A5 — the ledger fallback tries one project key** (`DF:21-36`). Fixed: a ledger session is
  looked up under every project key (`readTranscripts`).
- **F2 — a `--branch` re-run rewrites the committed record with an empty ledger** (`DF:340`).
  Fixed: archive writes the record once and leaves a committed one alone; there is no
  `--branch` re-run.
- **G2 — an undated archive directory sorts first** (`DF:371`). Fixed in the window: the
  directories keep their commit order (`retro.md`).
- **H2-H5, H7-H8** (`DF:387-393`): the window's git calls per commit, the parser copied three
  times, a circular import, `--since-retro` on a stale `origin/develop`, `--refresh-ledger`
  forgetting to recompute `rulings`. Fixed: one `git log` parse per window and one call for
  every second parent's subject; the price table parsed in `lib/prices.mjs` alone; the metrics modules import one way
  (transcripts, facts, records, prices, metrics, window, retro); the ref is fetched and its fetch
  age reported; no refresh.
- **#4 — a well-formed all-zero report when the sessions came from the ledger only** (`DF:171`).
  Fixed: no data is `null`, never a zero.
- **The cost baseline before 2026-09-30 double-counted** (`index.md:119`). `fromV1` carries the
  origin's tokens as they are; a window that spans that date compares figures measured two ways.
  Not fixed, and not fixable: the transcripts of that period are pruned on this machine.
