## Decisions

The developer's answers to the questions of the three drafts (2026-10-14):

1. One orchestrator. The main session runs `superpowers:subagent-driven-development` for all task
   groups and dispatches each task's implementer and reviewers, the capability-level agents,
   directly into the group's worktree. There is no per-group controller agent. At most 2-3 groups
   run at once. A single group runs as in the origin: one sequential pass in the change worktree.
2. The capability-level agents (origin `.claude/agents/adf-{mechanical,integration,architecture}.md`)
   are ported into the core plugin's `agents/`. They set effort and the turn ceiling per level
   and feed the metrics. The project-specific phrase is removed.
3. The whole-suite test command is a line in the host's planning guide `openspec/planning.md`.
   When the line is missing, apply finds the command in the project's own files, proposes it, and
   writes it there on the developer's confirmation. On a decline the report says the suite was
   not run; never a silent pass. The project stack plugin (iteration 12) may replace the line.
4. Prove-it-can-fail: for a test-first task the reviewer runs the new test against the parent
   commit's code (`git show <parent>:<path>` into a temporary file, no stash), and it must fail;
   then it must pass on the new code.
5. Worktree provisioning (dependencies, environment files, a per-worktree database) is the
   project stack plugin's hook `provision` (iteration 12), called for the change worktree and
   every group worktree. Without the plugin the core makes the worktree and nothing more. The
   worktree itself is the core's (iteration 04).
6. The push per group is the `forge` role's `push` operation (contract 1.2); with no forge plugin
   nothing is pushed. Commits are atomic: one task, one commit.
7. Dispatch naming and reply files ship now, with the port of `check-reply.mjs`: whole, every
   role, with a parity tool. `check-sdd-workspace.mjs` is ported too.
8. Change selection (the origin's `resolve` block) becomes one script and one instruction block,
   shared by apply, verify and archive. This closes D4-D7.
9. Ticking: a task is ticked when its dispatch returns, by a script. The origin's per-task tick
   guardrail is dropped.
10. Tree guard: a script snapshots HEAD and the porcelain status of the main checkout and of the
    target worktree before each dispatch, and compares them after it. Any difference stops apply.
11. Work added during apply (K2, H1): the out-of-plan file is appended to the owning task's
    `**Files:**` block as a dated "Added during apply" line.
12. The grammar of the `DUP` suppression marker is defined by the core's apply instruction; the
    review stage (iteration 09) points at it.
13. The Superpowers scripts are invoked as the instruction states; afterwards the core checks that
    nothing was written to `plan/`. No wrapper.
14. With no forge plugin, archive offers a local merge into the base and merges only on the
    developer's yes (iteration 10).
15. Rejected, with the reasons in their rows: `/tmp/develop-check`, the `LC_ALL=C` shell sweep,
    `config-apply-orchestration` (a product spec), the in-place cases, the surface-map rules of
    flow-text diffs, the group controller's brief and the per-task tick guardrail.
