## Decisions

The developer's answers to the eight questions of the first draft (2026-10-14):

1. The whole ledger script is ported in iteration 04, with its parity tool.
2. The worktree is part of the core: every change gets its own branch and worktree, for parallel
   work and isolation. The developer picks the base, the integration branch or the current one;
   the change merges back into its base, through the forge plugin when one is enabled.
3. `/adf:init` sets the branch policy: an integration branch and a list of other protected
   branches. The plan symbol check's apply phase reads the change's base instead of
   `origin/develop`.
4. The English-only check is its own plugin (iteration 05).
5. "Prefer extending an existing module" is a flow rule; "simplicity first" and "surgical
   changes" stay host conventions.
6. The propose commit message stays fixed.
7. How a project gathers information for a plan, and its checks that need the developer, are
   project scope: the planning guide `openspec/planning.md`, created by `/adf:init` and delivered
   by the engine to the artifacts that name it in the schema. The core names no hardware.
8. The symbol check prints one JSON object with the origin's exit codes.
