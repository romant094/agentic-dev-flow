# Roadmap

One capability per iteration. Every iteration leaves the repository with green tests and a
working `/adf:init`. A capability is ported when its lessons file (`docs/lessons/`) accounts for
every rule of the origin project: ported, or rejected with a reason.

Every deterministic step is a script: a script does its work the same way every time, and an LLM
varies with its context. The LLM keeps the work that needs reasoning: writing the artifacts and
the code, planning and grouping, review, the judgement checks and the talk with the developer.
Every iteration's plan lists the steps an LLM would do, and moves each one a script can do.

## Checks after every iteration

1. `npm test`: the unit tests and `scripts/check-lessons.mjs`, which proves every rule of the
   origin is ported with evidence, rejected, or pending on a named iteration.
2. Parity is retired from the release steps since iteration 16 (the developer's decision,
   2026-11-04). The parity tools in `scripts/parity/` compared each ported script with the
   origin's own script at the origin's `HEAD`; the switch (iteration 15) removed the origin's
   flow, so the comparison has nothing to run against. The harness stays in the repository as
   the record of what was compared. A release is checked by `npm test` and by a run of the
   changed commands in a scratch project.
3. `scripts/check-guide.mjs`, which runs inside `npm test`: every command, plugin, contract
   role, registry key and source file has a guide page, and every link resolves.
4. `scripts/guide-review.mjs` with no open finding, in every release step: one read-only agent
   per package checks the pages that the release's diff touches against the code.
5. A release adds its section to `CHANGELOG.md`.

A flow change updates its guide pages in the same commit.

The iteration record's `## Result` cites the checks it ran.
